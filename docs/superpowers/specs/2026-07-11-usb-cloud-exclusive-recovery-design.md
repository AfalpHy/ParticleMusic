# USB 云端独占恢复与真实缓冲设计

## 目标

统一修复 WebDAV、Subsonic/Navidrome 和 Emby 的云端独占播放：网络短暂停顿或后台调度抖动时保持 USB 独占，不回退系统输出；网络恢复后自动续播；切歌、重试和迟到回调不能造成界面歌曲与实际声音错位。

同时修正传输缓冲的真实语义。当前 Macaron 端点每秒传输 8000 个包，每个 URB 最多包含 16 个包，原生层最多保留 512 个 URB，因此 2250 ms 的后台目标实际只能达到约 1024 ms。设置页不能继续允许用户选择无法达到的目标。

## 范围

- 复用现有 `Library`、各云端 client、`MyAudioHandler`、`UsbExclusiveAudioEngine` 和 USB service，不新增 bridge、publisher、下载管理器或单用途 wrapper。
- WebDAV、Subsonic/Navidrome、Emby 保留各自请求构造，但下载结果、取消、残缺文件和重试语义保持一致。
- 只修改 USB 独占、云端缓存和对应设置/状态；不修改 `BackdropFilter`、`CoverArtWidget`、歌词页或横屏背景。
- 不做 HTTP Range 断点续传。真实断线后允许从头重试，先保证同一文件句柄能够恢复且残缺文件不会被误判为完整缓存。

## 统一下载语义

各云端下载方法统一返回 `Future<bool>`：只有服务器响应完整结束并成功写完文件时返回 `true`；取消、连接失败、响应中断和写入异常均返回 `false`。

所有下载都接收同一个 `CancelToken`，使用无限接收等待，并保留错误时的 `.part` 文件。短暂没有新字节不视为失败，避免应用进入后台后因固定接收超时删除正在被原生播放器读取的文件。

`Library` 仍是唯一的缓存协调点：

1. 首次下载前清理上次遗留的 `.part`。
2. 下载期间始终写同一路径，不在重试之间删除并重建 `.part`。
3. 返回 `false` 时保留 `.part` 并在一秒后重试；取消时停止重试。
4. 只有返回 `true` 后才把 `.part` 重命名为正式缓存并设置 `cacheExist`。

重试可以截断并从头写入同一文件，但不能删除后创建新的同名文件。这样 `GrowingFileDataSource` 已打开的文件描述符仍指向同一个 inode，能够看到长度重新增长并在数据追上播放位置后自动继续。

## 独占缓冲与后台恢复

未缓存云端歌曲仍先建立约十秒的压缩文件水位，再启动原生独占。播放追上下载位置时，`GrowingFileDataSource` 保持当前 USB 会话并等待 `.part` 增长；网络恢复后继续向解码器供给数据，不切换到共享输出。

Android 独占 worker 在入口设置音频线程优先级，降低大型前台应用抢占普通优先级线程导致 USB 队列耗尽的概率。该调整只作用于 USB 解码/写入线程，不改变 Flutter UI 或普通共享播放线程。

USB 在途队列与网络文件水位分开看待：USB 队列用于吸收短时调度抖动，云端 `.part` 水位用于吸收网络抖动。前台和后台 USB 缓冲设置统一限制在 50–1000 ms；已有超过 1000 ms 的偏好在读取时收敛为 1000 ms。传输状态显示的目标值必须与原生实际目标一致，不再显示 2250 ms、实际只有约 1024 ms。

## 切歌与状态一致性

每次独占启动携带播放会话标识，原生状态和位置回调原样带回。Dart 只接受当前会话的回调；旧 worker 的完成、错误或位置更新不能覆盖新歌状态。

PCM、DoP 和 Native DSD 切歌或停止时都不强制清空 USB 输出 URB，保持等时传输连续，避免队列断流产生音爆。会话标识负责隔离旧回调；DoP/Native DSD 继续使用静音填充跨过切歌空窗。

当新云端歌曲尚未达到独占起播水位时，播放状态保持加载语义；旧会话回调不得覆盖新歌状态。达到水位后才开始当前会话并恢复正常位置上报。

## 错误处理

- 网络短暂停顿：保持独占会话和 `.part`，等待并自动恢复。
- 下载连接真实中断：保留同一 `.part`，返回失败并重试；不提升残缺缓存。
- 用户切歌或清缓存：通过 `CancelToken` 停止旧下载，旧任务结束后才允许同路径的新任务开始。
- 原生 USB 错误或拔出 DAC：沿用现有系统输出回退；这与网络缓冲等待不同。
- 旧会话迟到回调：静默忽略，不触发回退、自动切歌或界面覆盖。

## 测试与验收

先运行现有云端下载测试确认当前失败，再按 TDD 修复。测试覆盖：

- WebDAV、Subsonic/Navidrome、Emby 在慢字节间隔下不会因接收超时失败。
- 三类来源下载中断均返回失败、保留 `.part` 且不提升残缺缓存，随后可以重试成功。
- 取消下载后停止重试并保留残缺文件。
- 超过 1000 ms 的后台缓冲偏好被收敛，原生遥测目标与实际队列能力一致。
- 旧独占会话回调不会更新当前播放状态。

使用 Flutter 3.44 执行相关 Dart 测试、Android Kotlin 测试和 `analyze`。WebDAV、Subsonic/Navidrome、Emby 的协议行为由本地测试服务器自动验证。随后仅构建 arm64 profile APK，在真机重点手工验证用户实际使用的 Navidrome：后台打开高负载应用、网络短断后恢复、连续快速切歌、暂停恢复和缓存完成后的再次播放。
