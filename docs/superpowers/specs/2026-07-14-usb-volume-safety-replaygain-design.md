# USB 音量安全、硬件同步与 ReplayGain 设计

## 背景

当前 USB 独占播放已经能够把用户音量和 ReplayGain 下发到 DAC 硬件音量，但真机日志暴露出四类安全和一致性问题：

1. iBasso 硬件音量写入或回读失败时，PCM 可以回退到数字衰减，DSD 却仍可能在没有安全衰减的情况下继续传输。
2. Android 远程音量面板与应用自绘音量提示同时出现。
3. DAC 物理旋钮的 32 字节 HID 通知没有被识别，应用和 `MediaSession` 保留旧音量，下一次手机音量键会从旧值计算。
4. Navidrome 音源文件包含 ReplayGain 标签，但在线曲目没有稳定获得对应元数据；把文件下载为本地歌曲重新扫描后才能显示。

日志还确认了一个独立的展示问题：24-bit FLAC 可能被 Android `MediaCodec` 解码成 16-bit PCM，再填充到 24-bit USB 槽位。界面不能把这种链路标记为真正的 24-bit bit-perfect。

## 目标

- 所有播放路径降低音量立即生效，任何增大音量的变化都受到统一限制。
- 切歌以及 PCM、DoP、Native DSD 切换时不出现突然增大的有效输出增益。
- DSD 只有在硬件音量已经写入并得到可信确认后才允许开始传输。
- DAC 旋钮、应用音量和 Android `MediaSession` 保持同一个逻辑音量。
- 手机物理音量键只显示系统音量面板，避免重复提示。
- Navidrome 优先使用 OpenSubsonic ReplayGain，文件标签作为可靠兜底。
- 状态页区分源位深、解码有效位深和 USB 槽位，避免错误宣称 bit-perfect。

## 非目标

- 本轮不替换 Android PCM 解码器，也不承诺恢复真正的 24-bit 解码精度。
- 不修改歌词页、背景、封面、转场或其它非 USB 页面。
- 不为所有 DAC 创建新的音量架构；厂商差异继续使用现有 DAC quirk/profile 机制。
- 不尝试在 DAC 固件应用物理旋钮变化之前拦截它。应用只能在收到硬件通知后校验并纠正异常上跳。

## 方案选择

### ReplayGain 来源

采用“API 优先、文件标签兜底”：

1. Navidrome 同步时直接保存 OpenSubsonic `Child.replayGain`。
2. 当前歌曲或预取歌曲缺少 ReplayGain 时，通过 `getSong` 请求一次详细元数据。
3. 已有完整缓存但数据库缺少 ReplayGain 时，扫描缓存文件并持久化结果。
4. 新下载完成后继续扫描文件，只补齐 API 缺失的字段，不覆盖服务器已经给出的有效值。

不采用“只信任 API”，因为服务器版本、兼容设置或旧数据库可能省略扩展字段；也不采用“必须下载完整文件后再播放”，因为这会破坏边下边播和云端切歌体验。

### 音量提示

Android 手机物理键使用系统远程音量面板，不再触发应用自绘提示。DAC 旋钮通知无法可靠强制唤起 Android 系统面板，因此仍使用现有应用自绘提示。这样既消除双层音量条，又保留 DAC 外置控制的可见反馈。

## 统一音量模型

应用继续使用 `0.0..1.0` 的逻辑用户音量，对 Android 暴露 `0..100`。硬件协议仍使用厂商寄存器值。

需要区分三类状态：

- **请求音量**：用户最终想要的逻辑音量。
- **已确认音量**：最近一次由 DAC 回读或可信写入确认的逻辑音量。
- **有效输出增益**：用户音量、ReplayGain 和 DSD 补偿共同计算后的实际目标。

手机物理键必须以最近一次已确认音量为基准。DAC 旋钮通知是硬件状态的权威来源；收到通知后更新应用状态和 `MediaSession`，但不能把同一个值再写回 DAC 形成回声循环。

## 音量上升保护

统一规则如下：

- 降低音量立即生效。
- 应用按钮、滑块、Android 远程音量请求单次向上最多推进 2 个百分级。
- 拖动到更高目标或长按时保存最终目标，以每 100 ms 最多 2 个百分级的斜率渐升。
- 新的降低请求会立即取消正在进行的向上渐升。
- 新的切歌、暂停、停止或 USB 会话代次变化会取消旧会话的渐升任务，避免过期任务写入新歌曲。
- ReplayGain 后到达时，任何额外衰减立即生效；任何有效增益增加都复用同一安全渐升。

DAC 物理旋钮由硬件先执行、应用后收到通知，无法做到事前限速。若通知显示单次向上超过 2 个百分级，应用立即把目标限制为“上一次确认值 + 2”并回写 DAC。该措施能迅速纠正异常跳变，但不能保证消除硬件已经产生的极短瞬时变化。

## 切歌与格式切换保护

切歌时记录上一首最后确认的有效输出增益。新歌曲的期望有效增益如果更低，则立即使用更低值；如果更高，则先从上一首值开始，再按安全斜率恢复。

对于具有独立 PCM/DSD 音量寄存器的设备：

- 两个寄存器仍映射到同一个逻辑用户音量。
- 进入 DSD 前先计算并写入 DSD 寄存器，退出 DSD 前先准备 PCM 寄存器。
- DSD 增益补偿只参与 DSD 寄存器目标，不修改 DSD/DoP 音频数据。
- ReplayGain 和 DSD 补偿共同产生的有效增益增加也必须受切歌保护。

## DSD 硬安全门

DSD/DoP 不允许使用 PCM 数字音量回退。原生层在提交第一批 DSD USB 数据之前必须满足：

1. 当前 DAC profile 声明支持对应硬件音量协议。
2. PCM/DSD 目标寄存器写入成功。
3. 设备返回可信读值，或者 profile 明确允许经过验证的写入确认方式。
4. 确认后的有效音量不高于安全起始目标。

任一条件失败都终止 DSD 独占启动并保持静音，不得继续满幅传输。上层收到明确状态后可以保持暂停或回退到用户允许的 PCM 共享路径，但不能静默继续 DSD。

## iBasso 双向同步

当前设备发出的音量通知为 32 字节 HID report，而现有解析只接受旧的 16 字节 `FE 01` 形态。适配应位于现有 iBasso 协议与 quirk/profile 代码中：

- 同时支持已经验证的旧 report 和当前 32 字节 report。
- 按 report 长度、命令/状态字段和数值范围验证，不把任意输入包误识别为音量。
- 把主动通知、命令响应和 ACK 分开路由。
- HID 命令保持串行，每次只允许一个待确认请求。
- 外部旋钮通知生成 `onUsbHardwareVolumeChanged`，包含硬件原始值、逻辑增益和当前 PCM/DSD 域。
- 上层收到通知后更新 `volumeNotifier` 和 Android playback info，不重复写回同值。

具体字节偏移必须由真机旋钮日志和官方应用行为交叉验证后写入测试，不能仅凭单个静态数据包猜测。

## Android 音量交互

- `androidAdjustRemoteVolume` 和 `androidSetRemoteVolume` 进入统一安全限速，但不增加 `usbVolumeOverlayNotifier`。
- Android playback info 始终发布最近确认的逻辑音量。
- DAC 主动通知继续触发应用自绘提示，并刷新 playback info。
- 锁屏、息屏和应用退到后台时继续由 `MediaSession` 的远程绝对音量处理手机物理键。

## ReplayGain 数据流

### 在线同步

`search3` 返回的歌曲继续通过 `MyAudioMetadata.fromOpenSonicMap` 解析四项 ReplayGain。同步完成后写入 Navidrome metadata 数据库，确保重启后仍可使用。

### 播放前补充

如果当前在线歌曲缺少首选模式的增益：

1. 先对当前歌曲调用 `getSong` 获取完整 `Child`。
2. 只补齐缺失且有效的字段并更新数据库。
3. 已有完整缓存时直接读取文件标签。
4. 对下一首预取相同信息，避免切歌时等待。

网络请求使用较短超时；失败不阻止播放，只记录缺失来源并使用 0 dB。不能为了 ReplayGain 强制等待整首下载。

### 播放中更新

若缓存下载完成后才得到标签：

- 当前歌曲重新计算音轨/专辑模式。
- 更低的有效增益立即下发。
- 更高的有效增益交给统一渐升逻辑。
- 非当前歌曲只更新数据库，等实际播放时再计算。

日志至少包含歌曲 ID、API 四项值、文件补齐值、选择模式、最终 dB、峰值限制和实际下发路径，日志使用英文且不包含认证信息。

## 位深诚实展示

状态模型区分：

- 源文件声明位深。
- 解码器实际输出位深。
- USB 端点槽位/子槽位位深。

只有采样率未变、解码有效位深不低于源位深、没有数字处理且 USB 数据布局符合源精度时，才能显示 bit-perfect。若 24-bit 文件实际解码为 16-bit 再填充到 24-bit USB 槽位，应显示真实解码精度，并把 bit-perfect 标记为不成立。

真正的 24-bit 软件解码器替换作为后续独立设计和提交处理。

## 错误处理与日志

- DSD 安全门失败必须产生明确的安全拒播状态，日志说明失败阶段，不输出敏感设备或账户信息。
- HID 未知包保留十六进制诊断，但按频率限流，避免淹没日志。
- ReplayGain API 和缓存解析失败不阻断普通播放。
- 所有异步回调携带播放/USB 会话代次，旧歌曲结果不能修改当前歌曲音量。

## 测试策略

### Dart 测试

- 上升限制、下降立即、取消过期渐升。
- 切歌有效增益不突然增加。
- Android 远程按键不触发自绘提示的纯逻辑。
- DAC 回报成为下一次手机按键的基准。
- OpenSubsonic `replayGain` 数值和字符串解析。
- `getSong` 补齐、旧缓存补齐、API 值不被文件值覆盖。
- 播放中 ReplayGain 降低立即、增加渐升。
- 位深和 bit-perfect 判定。

- 32 字节 iBasso 主动通知、响应和未知包路由。
- PCM/DSD 寄存器映射和补偿。
- DSD 硬件音量未确认时拒绝启动。
- PCM 硬件失败时仍可安全回退数字音量。
- 会话切换取消旧渐升和旧 HID 响应。
