# USB HID 连续音量写入安全设计

## 目标

修复 iBasso HID 回读曾经恢复成功后，后续单次瞬时超时仍被累计为永久只写状态的问题；同时阻止手机音量键在前一次 USB 音量写入完成前继续累计增大目标。保留 DSD 硬件音量不可信时立即暂停的安全门，并保证 PCM 数字兜底先完成衰减，再把 DAC 恢复到 unity。

## 根因

`IbassoReaderHealth.afterVerifiedReadback()` 当前只恢复 `readbackVerified`，没有清除历史 `failureCount`、`restartRequested` 与 `writeOnly`。因此一次已经恢复的旧超时仍会计入下一次失败，第二次瞬时超时会直接进入永久只写状态。

手机物理音量键当前会立即更新软件目标，并以未等待方式调用 `setExclusiveVolume`。一次 iBasso 音量写入需要串行发送多条 HID 命令并等待应答；如果设备暂时没有确认，用户继续按键会累计多个更高的软件目标，恢复后可能连续下发，产生突然增大的风险。

真机日志还证明 PCM 回读失效时存在交接顺序问题：旧实现先向 iBasso 写入 `register=0`（硬件 unity），然后才启用数字兜底，并从 unity 用 120 ms 平滑到目标衰减。该窗口会短暂暴露满幅 PCM，造成突然大音量。

## 方案

1. 已验证的 iBasso 回读视为一次完整恢复：清零失败计数和待处理读取失败计数，取消重启请求，退出只写状态，并标记回读可信。
2. 手机物理音量键的一次调整必须等待对应 USB 音量调用完成。在等待期间忽略后续物理音量键事件，不排队，也不合并到更高目标；一次异常最多保留一次 2% 调整。
3. 手机物理音量键改为软件显示值固定增减 2 个百分点，并继续限制在 0% 到 100%。滑条、DAC 自身旋钮、ReplayGain 与切歌路径不使用该按键忙碌门。
4. DSD 安全门保持现状：硬件音量未激活、回读未验证或进入只写状态时暂停。
5. PCM 回读失效时立即把当前用户音量与 ReplayGain 写入数字增益，不做从 unity 开始的平滑衰减；只有从数字兜底切回已经验证的硬件音量时，才允许平滑释放数字衰减。任何恢复 DAC unity 的写入必须发生在数字衰减生效之后。

## 验证

- Kotlin 单元测试复现“第一次失败、重启、成功回读、再次失败”的序列，确认第二次失败只请求重启而不会直接进入只写状态。
- Kotlin 单元测试确认硬件音量转 PCM 数字兜底时禁止平滑，数字兜底转已验证硬件音量时允许平滑。
- Dart 单元测试确认手机音量键固定增减 2%，并覆盖上下界。
- 代码审查确认手机按键处理在 USB 写入完成前保持忙碌，忙碌期间不会修改软件目标或再次下发。
- 运行 Android 原生单元测试、相关 Flutter 测试、Flutter analyze，并构建 arm64 Profile APK。
- 真机只做安装、启动和日志检查；不自动发送音量增大按键。连续上调由用户在低音量条件下手动验证。
