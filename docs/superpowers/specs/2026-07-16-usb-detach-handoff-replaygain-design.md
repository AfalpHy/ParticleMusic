# USB 拔出安全交接与全路径 ReplayGain 设计

## 背景

当前 USB 独占播放在 DAC 拔出后存在三组相关问题：

- USB 设置页的“当前媒体音量”始终绑定 DAC 专属音量。没有 DAC 时拖动只会改写记忆值，不会控制共享播放器，因此看起来可以操作但实际无效。
- 独占中断回退只使用原生层最后一次 inactive 状态携带的位置。设备突然移除时，该位置可能已经归零或落后；暂停状态下又不会继续写 USB，因而可能迟迟没有原生错误回调，导致界面仍显示独占有效。
- ReplayGain 已有独占和共享两条应用代码，但界面只读取独占状态中的 `replayGainMilliDb`。共享路径没有统一的实际应用状态，而且增益在媒体打开前下发，无法可靠证明打开媒体后仍然生效。

现有日志验证了事件顺序问题：设备已经枚举为零后，暂停会话仍保持 active；直到再次恢复独占才因 `No such device` 进入回退。回退收到的位置只有原生最后一次上报值，不能作为突然拔出的唯一位置来源。

## 目标

- DAC 拔出后立即退出独占并刷新输出状态，不依赖后续 USB 写入失败。
- 保留最后可信播放位置，但为了避免手机扬声器突然出声，拔出后始终保持暂停。
- 恢复共享输出自己的音量，不用 DAC 音量覆盖手机或其它共享输出。
- 无 DAC 时保留显示 DAC 记忆音量，但控件灰置且不可操作。
- ReplayGain 对独占和共享输出都生效，并展示实际应用结果。
- 将 ReplayGain 从 `Bit-perfect` 文本中拆出为独立信息行。
- 设备移除、原生 `ENODEV` 和迟到 inactive 回调不能重复执行交接。

## 范围

本次只修改 USB 设备事件、独占到共享输出交接、相关音量状态、ReplayGain 应用状态和音频输出面板。

不修改歌词页、封面、背景、转场、均衡器或其它非必要播放器视觉。保留现有每设备 DAC 音量记忆、硬件音量安全状态机和 USB 音量键接管逻辑。

## 方案选择

采用由 `MyAudioHandler` 统一协调交接的方案。Android 原生层继续负责发现设备和上报独占状态，不直接打开共享播放器；界面监听器继续只负责提示，不承担播放状态变更。

相比在原生层直接回退，该方案可以复用现有歌曲资源解析、云端鉴权、播放器状态和 ReplayGain 逻辑。相比在多个回调中分别修补，它能让设备移除和后续原生错误归并为同一次交接。

## 设备移除与安全交接

`MyAudioHandler` 监听现有 `usbAudioEventNotifier`。收到当前 USB 音频设备的 removed 事件时：

1. 从 Dart 最近持续接收的独占位置保存最后可信位置，同时保存当前歌曲和加载代次。
2. 立即将本地独占状态切换为非活动，使播放状态栏和音频输出面板同步刷新。
3. 立即更新播放状态为暂停，取消音量渐变和独占增益写入。
4. 恢复共享输出音量。
5. 以暂停方式打开当前歌曲的共享播放器。
6. 媒体打开成功后应用共享 ReplayGain，再 seek 到保存的位置。
7. 保持暂停，等待用户手动继续播放。

交接使用现有加载代次和一个进行中标记隔离。相同会话后续到达的 `No such device`、`ENODEV` 或 inactive 状态只负责完成原生资源清理，不再次打开歌曲或覆盖位置。切歌发生后，旧交接结果因加载代次不匹配而丢弃。

如果共享媒体打开失败，状态仍保持暂停和非独占，记录开发者日志，不自动从头播放，也不重新启动已经移除的 DAC。

## 播放位置语义

播放期间持续保存 Dart 侧最后一次可信独占位置，而不是只在 inactive 回调到达时读取位置。设备移除时优先采用该位置；原生 inactive 状态中的位置只有在不倒退且属于当前播放会话时才可更新它。

共享播放器必须先打开、再 seek。位置恢复完成前不得播放，避免从零点短暂出声。暂停拔出和播放中拔出采用相同流程，最终都停在原位置。

## 音量所有权

继续保留两套音量：

- 共享输出音量：手机扬声器、蓝牙和系统共享音频路径使用 `_sharedUserVolume`。
- DAC 音量：按 USB 设备 VID/PID 保存，继续使用现有设备音量映射。

进入独占前读取目标 DAC 的记忆音量；退出独占时恢复共享音量。设备 removed 状态不得把空设备键对应的默认 DAC 音量写入共享音量。

USB 设置页的“当前媒体音量”在存在可用 USB DAC 时保持现有行为；无 DAC 时仍显示最近的 DAC 记忆值，但 Slider 灰置、`onChanged` 和 `onChangeEnd` 均不可用。它不会改为共享音量控制器，避免 USB 设置页同时承担两种音量语义。

## ReplayGain 全路径状态

在现有播放与 ReplayGain 代码附近维护一个轻量的实际应用状态，包含：

- 当前选择得到的 ReplayGain dB；
- 实际应用的 dB；
- 是否应用成功；
- 当前应用路径为独占硬件、独占数字或共享数字；
- 当前歌曲或播放代次，用于忽略迟到结果。

不新增 manager、bridge 或只转发调用的抽象。

独占路径在硬件或数字音量写入返回后更新实际状态。共享路径在 `_player.open` 完成后设置 `volume-gain`，成功后再发布实际状态；打开前不把 ReplayGain 标记为已应用。标签补充完成、ReplayGain 模式变化和音量导致输出余量变化时，沿用现有安全增益渐变并重新发布状态。

当模式关闭、歌曲没有标签或有效增益为 `0 dB` 时，状态明确记录为关闭、无标签或 `0 dB`，避免把“没有增益”误报为应用失败。共享播放器设置属性失败时显示未应用并记录英文开发者日志。

## 音频输出面板

`Bit-perfect` 行只保留当前音量处理方式、硬件音量验证状态和位深转换，不再拼接 ReplayGain。

信号输出区域增加独立“回放增益”行：

- 成功应用时显示实际 dB，例如 `-8.4 dB`；
- 正在等待标签或播放器打开时显示同步中的本地化状态；
- 有标签但设置失败时显示未应用；
- 模式关闭时显示关闭；
- 没有适用标签时显示无标签。

该行在独占和非独占输出下都存在，读取统一实际应用状态，而不是直接读取原生独占状态。

## 测试与验证

先补充失败测试，再修改实现。至少覆盖：

- 播放中移除 DAC：立即暂停、退出独占、恢复共享音量、打开共享媒体并恢复原位置，但不自动播放。
- 暂停时移除 DAC：无需再次点击播放即可刷新非独占状态，并保持原位置暂停。
- removed 事件后再到达 `ENODEV` 或 inactive：只执行一次共享媒体交接。
- 交接过程中切歌：旧会话不得 seek 或覆盖新歌曲状态。
- 无 DAC：USB 媒体音量控件不可操作，不改变共享音量或空设备默认值。
- 不同 VID/PID 的 DAC 音量继续独立保存。
- 共享播放器打开后应用 ReplayGain，标签更新和模式变化会重新应用。
- 独占与共享路径均发布实际 ReplayGain 状态；失败和无标签状态不误报。
- 输出面板的 ReplayGain 独立于 `Bit-perfect` 展示。

执行相关 Dart 测试、`gen-l10n`、针对修改范围的 `analyze`、Android 原生测试和 arm64 profile 构建。真机重点验证播放中拔出、暂停拔出、本地与 Navidrome 歌曲、重新插入同一 DAC 以及切换另一 DAC。
