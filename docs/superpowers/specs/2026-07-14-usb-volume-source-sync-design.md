# USB 音量来源与设备同步设计

## 目标

解决手机物理音量键响应过慢、DAC 旋钮回报受“未验证”状态影响，以及普通媒体音量与 USB 独占音量互相覆盖的问题。修改仅限 USB 音量、ReplayGain 交接和对应状态同步，不改变其它播放器页面与交互。

## 音量来源规则

### 手机物理音量键

- 相对音量键每次调整 5%，不经过现有的 2% 用户音量慢速斜坡。
- Android 绝对音量请求降低时立即生效。
- Android 绝对音量请求提高时，单次最多提高 20%。
- 每次调整仍通过现有 USB 硬件音量协议写入 DAC。

### DAC 物理旋钮或按键

- DAC 主动上报的音量是最终事实来源。
- 应用立即同步界面、Android 远程音量和持久化记录，不做 2% 限速。
- 同步设备事件时不得把旧值或限速后的值反向写回 DAC。
- 有效的主动音量事件同时恢复该 HID 会话的“已验证”状态。

### 自动增益变化

- ReplayGain 降低立即生效；提高时每 100ms 最多提高 20%。
- DSD/PCM 路径切换、硬件音量失效和未知初始状态继续使用严格安全门。
- DSD 硬件音量未确认时保持暂停和 DSD 静音帧，不允许恢复到 0 dB。

## 普通媒体音量与 USB 独占音量

- 普通共享播放继续使用现有媒体音量，不被 USB 独占修改。
- USB 独占音量按 DAC 的稳定键 `VID:PID` 单独保存。
- 进入 USB 独占时按以下顺序决定初始音量：
  1. DAC 当前可信回读或主动上报值；
  2. 当前 `VID:PID` 上次保存的 USB 独占音量；
  3. 独立的 30% 安全默认值。
- 退出 USB 独占后恢复普通共享播放原有音量，不把 DAC 音量写回普通媒体音量。
- USB 设置页“当前媒体音量”在 DAC 已连接时显示当前设备的 USB 独占音量；未连接时显示独立 USB 默认值，不显示普通媒体音量。
- 手机音量键、USB 设置页滑块和 DAC 主动事件更新当前设备的 USB 独占记录。

## HID 重连与“未验证”状态

- 临时关闭或重建同一物理 DAC 的 HID 控制连接时，保留该设备上一次已验证的寄存器目标。
- 只有 USB 设备真正断开、切换到不同 `VID:PID` 或会话被永久清理时，才清除内存中的可信目标。
- 有可信目标时允许安全重写并重新回读，不进入无意义的“未验证”过渡。
- 收到 DAC 主动音量事件后，将硬件音量标记为活动且已验证，并更新可信目标。
- 真正无法确认硬件音量时，不得向 Android 报告一个仍可控制的旧硬件音量；PCM 使用数字音量状态，DSD 进入安全暂停。

## 数据流

1. 手机物理键通过 Android 远程音量回调进入音频处理器。
2. 音频处理器应用 5% 相对步长或 20% 绝对上升边界，并更新当前 USB 设备音量。
3. USB 原生层写入并回读 DAC；成功后更新已验证状态。
4. DAC 旋钮事件由 HID 读取线程解析，直接同步音频处理器与设备音量记录，不触发反向写入。
5. 切换普通输出和 USB 独占时分别恢复各自的音量域。

## 验证

- Dart 单元测试覆盖手机键 5% 步长、绝对上升 20% 边界、DAC 事件不限速、ReplayGain 20% 上升边界和普通/USB 音量隔离。
- Kotlin 单元测试覆盖同设备 HID 重连保留可信目标、不同设备清除目标和主动事件恢复验证状态。
- 真机分别验证本地文件、Navidrome `.part` 流式文件和下载完成缓存文件。
- 真机日志必须不再出现连续的 `No trusted previous iBasso hardware volume`，DAC 旋钮后 Android 音量立即一致。
- DSD 切歌期间继续确认无 `register=0`、无数字满幅回退。
