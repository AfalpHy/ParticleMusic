# USB 跨参数切歌静音重锁设计

## 背景

USB 独占播放在会话参数完全相同时会复用现有等时端点，不清空在途 URB，因此同采样率 PCM 手动切歌没有明显音爆。采样率、位深、声道或输出类型变化时，当前实现会执行 `hardCloseSession("device or stream parameters changed")`，丢弃旧 URB、释放接口、重新选择 alt setting 并配置 DAC 时钟。

真机复现表明，手动从一种输出参数切换到另一种参数时会出现小音爆；同参数热复用正常。一次复现中，硬关闭后 iBasso HID `command 65` 回读超时，硬件音量同步被冻结。因为硬关闭同时清除了同一 DAC 的最后可信硬件目标，PCM 安全逻辑无法保留可信值而暂停播放，后续切歌也无法恢复；状态同时变成 `hardware=false`、`digital=false`，界面误显示“原始数字电平”。

本设计同时解决三个同一切换边界上的问题：

1. 旧流仍处于非零波形时被突然截断；
2. 新时钟尚未稳定时就提交新曲有效音频；
3. 同一 DAC 重配时丢失可信硬件音量，瞬时 HID 回读失败导致 PCM 永久暂停。

## 目标

- 同参数手动切歌继续热复用，不增加静音或延迟。
- 跨采样率、位深、声道或 PCM/DoP/Native 类型切换时允许增加约 150–300ms 静音。
- 跨参数手动切歌不出现小音爆，新歌曲能够正常开始播放。
- 同一物理 DAC 重配时保留最后可信硬件音量；瞬时回读失败不能让 PCM 因缺少可信值而暂停。
- DSD/DoP/Native 继续使用现有硬件音量安全门，不能因消除音爆降低安全性。
- 不自动播放，不调用 Android 系统音量，不发送音量增加命令，不恢复 unity。

## 非目标

- 不改变同参数自然连播和热复用手感。
- 不为共享输出、非 USB 页面或播放器视觉做改动。
- 不依赖某一个 DAC 型号的硬件静音命令。
- 不改变 ReplayGain、DSD 补偿或硬件音量映射算法。
- 不通过延长 HID 超时掩盖 reader 故障。

## 方案比较

### 双端静音护栏（采用）

旧流先输出格式合法的渐弱/静音尾部，等待其进入并播放出 USB 队列；重设接口和时钟后，新流先输出格式合法的静音预卷，再提交有效音频。同时保留同一设备的可信硬件音量。

该方案同时覆盖旧流截断、DAC 重锁和新流首包三个音爆来源，代价是跨参数切歌增加有限静音。

### 仅新流静音预卷（不采用）

只在新时钟配置后预送静音。改动较小，但旧曲仍可能在非零电平被截断，无法可靠消除手动切歌音爆。

### 硬件静音包围重配（不采用）

切换前写 DAC 硬件静音，完成后恢复。该方案依赖设备协议，而当前故障恰好包含 HID 回读超时，可能引入冻结或错误音量，不适合作为通用行为。

## 架构与数据流

不新增通用 manager、bridge 或 adapter。切换协调保留在现有 `UsbExclusiveAudioEngine`；Dart 只区分“替换当前独占播放”和普通停止。

### 上层请求顺序

手动切歌时，如果当前正在 USB 独占，并且新歌曲也可以进入独占路径，`audio_handler.dart` 不再先调用普通 `stopExclusivePlayback()`。上层先完成新歌曲能力、路径和请求参数准备，再以替换语义调用现有独占启动通道。

原生层在旧会话尚可用时解析新文件，得到新会话签名：

- USB 设备 ID；
- 输出采样率；
- 声道数；
- 会话位深；
- 输出类型：PCM、DoP 或 Native DSD；
- Native DSD 字节排列。

若新歌曲无法进入独占路径，上层再按现有顺序主动停止旧独占并回退共享输出。预检失败不能把旧会话留在半关闭状态。

### 同参数热复用

新旧会话签名完全一致时，沿用现有热复用：

1. 停止旧解码线程；
2. 不 flush、不关闭接口、不重配时钟；
3. 保留在途 URB，并接入新曲。

该路径不得生成切换尾部、静音预卷或额外延迟。

### 跨参数旧流收尾

签名变化时，原生层先让旧写线程进入“切换收尾”，再停止会话：

- PCM：打包器记录每声道最后一个已转换样本，生成约 10–20ms 单调渐弱到零的尾部，再补零样本。渐弱只发生在用户主动丢弃的曲尾，不改变正常播放中的数字增益和位完美判定。
- DoP/Native DSD：复用现有会话级编码器和 packetizer，生成格式合法的 DSD 静音；DoP 标记相位和 Native 帧对齐必须连续。

尾部写入后，通过现有传输遥测轮询待处理输出 URB。达到静音尾部已播放、队列为空或仅剩可安全丢弃的静音数据时继续关闭。等待必须有上限，整个跨参数静音预算约 150–300ms；超时记录英文诊断并执行安全关闭，不能无限卡住切歌。

### 新会话静音预卷

旧会话关闭后按现有逻辑打开新 alt setting、配置时钟并执行音量安全检查。安全检查通过后，在新解码器提交有效音频前先写入约 80–120ms 新格式静音：

- PCM 使用目标采样率、声道和 USB slot 宽度的零样本；
- DoP/Native DSD 使用新会话编码器生成合法静音。

预卷完成后才发送新曲首个有效音频包。静音时长使用通用默认值；现有 `clockSetCurDelayMs` 仍保留为设备 quirk，但不以型号硬编码本功能。

## 硬件音量与会话隔离

### 保留条件

只有新旧设备 ID 相同、硬件音量协议相同且旧目标已经可信验证时，跨参数重配才能保留最后可信硬件目标。设备变化、协议变化、目标未验证或 write-only 时必须清除，不能跨设备借用状态。

### 失效顺序

切换开始时：

1. 递增音量 session generation；
2. 清除协调器中的运行外待处理目标；
3. 停止旧 HID reader，失效其 pending response、重启回调和主动事件；
4. 关闭旧音频接口，但按上述条件保留可信硬件目标。

旧 connection、旧 reader generation 或旧音量 session generation 的异步失败不得更新新会话的冻结、暂停或状态字段。

### 新会话验证

- 首次回读成功：按现有逻辑接受目标并继续播放。
- 首次回读超时：PCM 若有可信旧目标，可以先发送零样本预卷，等新时钟和 reader 稳定后只执行一次有界恢复与回读；DSD 在验证成功前仍不得提交任何 USB 音频数据，只做有界等待和 reader 恢复，验证成功后才发送 DSD 静音预卷。
- PCM 再次失败且存在可信旧目标：保持该硬件值，冻结音量调节但不暂停播放；状态保持 `hardwareVolumeActive=true`、`digitalVolumeActive=false`、`hardwareVolumeFrozen=true`，界面显示“DAC 硬件音量（同步失败）”，不能显示“原始数字电平”。
- PCM 没有任何可信旧目标：继续执行现有安全暂停，不能猜测硬件值。
- DSD/DoP/Native：继续要求硬件音量可信确认；无法确认就保持暂停或拒绝启动，不允许数字音量兜底。
- 后续可信回读或 DAC 主动音量事件可以解除冻结；不得自动恢复曾因 DSD 安全门暂停的播放。

## 错误处理

- 旧线程无法在现有有界时间内退出：关闭旧会话并记录阶段，不继续叠加等待。
- 静音尾部写入失败或 URB 排空超时：记录失败阶段，安全关闭后仍尝试以新会话静音预卷起播；不得无限等待。
- 新接口、时钟或端点配置失败：沿用现有独占失败和共享输出回退。
- 新静音预卷失败：不提交有效音频，关闭新会话并返回明确错误。
- HID 验证失败：按 PCM 可信旧值与 DSD 严格安全门分别处理，不能统一降级为原始数字电平。

## 诊断

开发者日志和 session diagnostics 使用英文，至少记录以下阶段及耗时：

```text
reuse
old-tail-started
old-output-drained
old-session-closed
new-clock-configured
hardware-volume-verified
hardware-volume-frozen
new-silence-preroll
new-audio-started
```

日志应包含旧、新会话签名和阶段耗时，不记录完整媒体路径，不打印每个样本或每个静音包。

## 测试

### 纯逻辑与 Android 单元测试

- 完全相同的会话签名选择热复用。
- 任一采样率、位深、声道、输出类型或 Native 排列变化选择静音重配。
- PCM 16/24/32-bit 收尾从每声道最后样本单调趋近零，末帧为零且不溢出。
- DSD 收尾和预卷使用合法静音，并保持 DoP 相位和 Native 对齐。
- 同设备、同协议、可信目标才保留；设备或协议变化必须清除。
- 旧 generation 的 HID 失败不能冻结或暂停新会话。
- PCM 有可信旧值时回读失败保持播放并冻结控制；无可信值时仍安全暂停。
- DSD 现有安全门测试继续通过。
- 硬件音量冻结且可信时不能映射为原始数字电平。
- URB 排空超时返回有界决策，不形成无限等待。

### 自动验证

- Android 目标测试和完整 `app:testDebugUnitTest`。
- Flutter USB 服务、远程音量和安全增益回归测试。
- `flutter analyze`。
- arm64 Profile APK 构建。

### 真机验收

真机阶段不自动播放、不发送音量命令，由用户手动操作：

1. 同采样率 PCM 手动切歌：延迟和现有表现不变。
2. `44.1 ↔ 48/96/192 kHz`：允许短静音，无小音爆，新曲自动正常播放。
3. PCM ↔ DoP/Native DSD：允许短静音，无小音爆；DSD 音量验证失败时仍安全暂停。
4. 日志中旧 reader 失败不修改新会话；PCM 有可信值时不出现无法恢复的暂停。
5. 状态不误显示“原始数字电平”，不出现硬件音量突然增大。

## 提交边界

实现只修改本设计直接涉及的 USB 独占切换、传输尾部、音量会话隔离及对应测试。不得覆盖工作区已有的 `UsbExclusiveAudioEngine.kt`、`audio_handler.dart`、`audio_output_panel.dart`、云端恢复文档和 generated plugin 文件修改；不得混入非 USB UI、歌词、背景或播放器视觉改动。
