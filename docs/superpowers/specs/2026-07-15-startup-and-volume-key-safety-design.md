# 启动恢复与手机音量键安全设计

## 目标

1. 应用恢复上次播放状态时，ReplayGain、歌词、封面或缓存标签读取无论超时、卡住还是失败，都不得阻塞 Flutter 首帧。
2. USB 独占播放期间，手机物理音量键不再使用 Android 远程音量通道，避免系统音量条的绝对索引误写入 DAC 音量。
3. 保留 DAC 物理旋钮的双向同步、自绘音量条和现有音量突增保护。

## 启动恢复

- 设置、音乐库、播放队列和基础播放状态仍在 `runApp()` 前加载，保持原有页面依赖与状态结构。
- 上次歌曲的实际打开和网络/元数据补齐改为首帧之后执行，不再阻塞 `runApp()`。
- 播放所需的 ReplayGain 优先使用数据库已保存值。API 和已完成缓存中的标签补齐属于后台增强；失败时使用 0 dB，并通过现有通知机制在成功后更新当前歌曲。
- 缓存标签解析不得成为歌曲打开的前置条件。异常缓存只记录开发者日志，不删除用户数据，也不阻止播放或启动。

## 手机物理音量键

- USB 独占音量可用且应用在前台时，由 `MainActivity` 拦截音量加减键并把相对方向传给 Dart。
- Dart 继续按现有分贝步长和突增限制调整当前 USB 音量，同时触发 `UsbExclusiveVolumeOverlay`。
- 始终向 Android 发布本地音量播放信息，不再发布 `RemoteAndroidPlaybackInfo`，从根源上取消系统远程绝对音量条及其回调。
- 应用后台、已退出或熄屏时不接管手机音量键；按键不得修改 DAC 音量。系统媒体音量可能变化，但与按设备保存的 USB 独占音量相互隔离。
- DAC 自身旋钮通知继续回读、保存并触发自绘音量条，不受手机按键策略影响。

## 安全边界

- 手机按键只发送相对方向，不接收系统提供的绝对百分比。
- 音量降低立即生效；音量提高继续受现有单步分贝上限和渐升机制约束。
- DSD、PCM、ReplayGain 与 DSD 补偿仍使用最终有效输出增益保护，不恢复任何满幅回退路径。

## 验证

- 单元测试证明 Android 播放信息始终为本地模式，远程绝对音量回调不再参与 DAC 控制。
- 单元测试证明前台按键事件仅在 USB 独占音量可用时生效，并触发相对安全步进。
- 回归测试证明上次歌曲恢复不会阻塞首帧，ReplayGain 补齐不会成为 `load()` 的前置条件。
- 执行相关 Flutter 测试、`flutter analyze`、Android 原生单元测试和 arm64 Profile/Release 构建；真机验证前台按键、自绘音量条、后台按键隔离及异常歌曲启动恢复。
